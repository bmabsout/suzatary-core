# Structural audit of `web/`, 2026-09-10

The app has just taken a large design pass (13 commits, merge `28edac1`) on top
of a week of feature work: chains as destinations, the Inbox, `proposal.ts`,
`theme.ts`, `undo.ts`, the filter strip, the left rail. This is that tree read
for structure alone against CLAUDE.md's Code section and the web-app paragraph
in Layout, in the shape of `docs/AUDIT-2026-09-09.md`. Semantics are out of
scope; nothing below changes a number, a payload or a stored byte.

Tree at the audit: 62 files under `web/src` (12,479 lines, the generated wire
excluded), `web/src/generated/wire.ts` 922, `web/static/style.css` 3,491,
`web/test` 20 files / 205 node tests, `web/e2e` 12 files / 46 browser scenes.
`nix develop .#triage -c tsc --noEmit -p web` is **clean**, and the tree holds
**zero** `any`, zero `@ts-ignore`, zero non-null assertions, and exactly one
`innerHTML` assignment.

The short answer to the question asked: it still reads as one program. The
rules are all still stated, still mostly kept, and the design pass did not
introduce a second architecture. What it introduced is *restatement* — the same
five-line helper written four and five times, a breakpoint spelled a third way,
a filter literal copied — and it left behind a set of comments that describe an
app that no longer exists. One finding is not drift at all but a hole in a
mechanism, and it is first.

## Findings

1. **The one-door gate silently skips two source files.** `web/src/card.ts:275`
   spells its reserved list key as a literal NUL byte
   (`const DIVIDER = "<U+0000>divider"`, written as the byte and not as `\0`),
   and `web/src/force.ts:107` uses a literal NUL as an edge-key separator.
   `grep -I` classifies both files as binary and skips them, and `-I` is on all
   three of `scripts/build-web.sh`'s gate greps (lines 76, 81). Demonstrated:
   `grep -RIn --include='*.ts' -e 'DIVIDER' web/src` returns **nothing** while
   `grep -Ran` finds it at `card.ts:275`. So the app's busiest renderer (415
   lines, every card and the keyed list) and the graph layout are entirely
   outside the escaping gate — an `innerHTML =` added to `card.ts` tomorrow
   builds green. CLAUDE.md's core principle is that nothing load-bearing is left
   to discipline; this invariant currently *is* discipline in two files and
   nobody could tell by reading.
   *Fix:* write the sentinels as `"\u0000"` escape sequences (identical runtime
   value, plain-text file), drop `-I` for `--binary-files=text`, and make the gate
   assert that the number of `.ts` files it scanned equals the number `find`
   reports — a gate that can skip a file must say so.
2. **The gate's vocabulary is four forms out of eight.** `build-web.sh` refuses
   `.outerHTML`, `insertAdjacentHTML`, `document.write` and an `innerHTML`
   assignment. It does not mention `DOMParser`, `Range.createContextualFragment`,
   `setHTMLUnsafe`/`parseHTMLUnsafe`, or `srcdoc` — every one of which turns a
   string into markup, and none of which is in the tree today (verified with
   `-a`). The door-count check (`grep -c` on `rich.ts`) also counts *lines*, so
   two assignments on one line read as one. The rule CLAUDE.md states is "never
   markup parsed from a string, with ONE counted exception"; the mechanism
   enforces a named subset of that rule.
   *Fix:* add the four missing forms to the banned list and count occurrences
   rather than lines (`grep -o … | wc -l`).
3. **`format.ts` declares "one chip style for the whole app" and four modules
   ignore it.** `format.ts:15` exports `tag(label, kind)`; `card.ts:67`,
   `todoview.ts:59`, `pages/mail.ts:35`, `pages/message.ts:34` and
   `pages/thread.ts:27` each define a byte-identical private `chip(label, kind)`.
   `format.tag` has exactly one caller (`pages/chain.ts`). Five copies of a
   two-line function is the "same shape written twice" this repo keeps writing
   down, and the file that was supposed to be the one place says so in its own
   doc comment.
   *Fix:* delete the five locals, rename `format.tag` to `chip` (the word the
   call sites and the stylesheet already use), import it.
4. **The back button is written four times.** `todoview.ts:63`,
   `pages/thread.ts:31`, `pages/briefing.ts:24`, `pages/message.ts:38` — same
   body, same `window.history.length > 1 ? back() : hash = …` fallback, same
   comment about a deep link opened cold, differing only in the label and the
   fallback route. Three of the four carry a comment saying the other pages do
   the same thing, which is the tree noticing the duplication and keeping it.
   *Fix:* `backButton(label: string, fallback: Route)` in `page.ts` (or beside
   `hrefOf`), four call sites.
5. **The detail pane is built three times.** `pages/todos.ts:256–291`,
   `pages/links.ts:97–130` and `pages/history.ts:90–105` each construct
   `.detailpane`, a `.panehint` block with the same two-paragraph shape, and
   (in two of the three) a near-identical `showPane(id)` that destroys the old
   `Mounted` and mounts `todoview`. `todoview.ts` is ONE function precisely so
   the pushed screen and the pane cannot drift; the *frame* around it now has
   three implementations that can.
   *Fix:* `pane.ts` — `detailPane({lead, legend})` returning
   `{node, show(id), destroy()}` — three call sites.
6. **`pages/todos.ts::mount` is 620 lines.** (`web/src/pages/todos.ts:192`.)
   Inside one closure: the filter strip, the facet chips, the keyed list, the
   detail pane, a seven-field add sheet with its own submit, and the
   `KeyTarget`. `pages/links.ts::mount` is 376, `pages/graph.ts::mount` 347,
   `pages/history.ts::mount` 245. The file is 813 lines with no seam below the
   module. Nothing here is wrong; it is unreadable in one sitting and untestable
   below the browser suite, which is the same objection finding 9 of the Rust
   audit made about `core/agent.rs`.
   *Fix:* lift the add sheet to `web/src/addsheet.ts` (`{node, open(), close()}`,
   it already talks only to `draft.ts`, `api.authorTodo` and `sync.append`) and
   the filter strip to `web/src/filterbar.ts` (`{node, filter(), onChange}`,
   already pure logic in `todos.ts`). `mount` then reads as: cache, list, pane,
   keyboard.
7. **The seal-and-append sequence is written three times.** `acts.ts:153`
   (`perform`), `acts.ts:191` (`undoOrRedo`) and `pages/todos.ts:581` (`submit`)
   each do: check `writesAs`, `await loadCore()`, `sealingOn(held())`, refuse on
   `null` with the same sentence, `sealObject(core, [on], event)`,
   `append({hash: object.name, literal: object.literal}, [on])`. `perform` and
   `undoOrRedo` differ only in which event they hand over and whether they toast
   an undo offer. This is the one path by which anything this browser wrote
   reaches the chain; three copies of it is three places to get the head wrong.
   *Fix:* one `sealAndAppend(event: string): Promise<void>` in `acts.ts`, called
   by all three; `perform` and `undoOrRedo` collapse to "build the event, then
   this".
8. **Comments narrate an application that is gone.** Forty-odd headers and doc
   comments across `web/src` cite Python modules deleted on 2026-09-08:
   `api.ts:4` ("Every type below is one `json_*` function in
   `suzatary/view.py`"), `format.ts:2,7` (`web.py::_pct`), `todos.ts:83`
   (`suzatary/instance.py::CATEGORIES`), `stale.ts:7` and `cache.ts:6` and
   `pages/todos.ts:6` (`fpl.py`), `rich.ts:15,28` (`document.py::escape_markup`,
   `markup.py::suspicious`), `conflicts.ts:7` (`prodrome/registers.py`),
   `verify.ts:8` (`suzatary/web.py`), `draft.ts:9` (`webapp._ratio`),
   `series.ts:6` (`tests/test_view.py`), plus `webapp.py`, `mail.ops.*` and
   `view.py` throughout. This is finding 7 of the Rust audit, one directory
   over, and it was not swept when the Rust was. (`events/objects/<hash>.py` and
   `conformance/*.py` are real filenames and stay.)
   Worse, three comments are not merely historical but **false**:
   - `palette.ts:11–14`: "There is no theme command, because there is no theme to
     toggle: the palette follows `prefers-color-scheme` and a stored preference …
     was rejected". `theme.ts` shipped in this very pass with three states, a
     stored preference and a control in the sheet.
   - `local.ts:7`: "Nothing load-bearing is kept here: the one client is the
     remembered filter." There are four clients — `sync.ts:34`, `chain.ts:29`,
     `theme.ts:24`, `pages/todos.ts:60` — and one of them is the fold cache.
   - `pages/links.ts:9`: "the colour of every dot is the band of the number the
     server sent". `bandOf` was replaced by the continuous ramp in this pass
     (`todos.ts:19–42`); the page passes `--fulfil` at `links.ts:268`.
   Stale counts round it out: `main.ts:4` "Twelve pages" (the switch has 15 plus
   `unknown`), `chain.ts:14` "thirteen arms" (`Route` has 17), `palette.ts:10`
   "the six destinations" (`DESTINATIONS` has 11).
   *Fix:* rewrite every header in the present tense naming the Rust item that
   holds the rule; delete the three that are wrong; replace the counts with the
   name of the thing that is exhaustive (`Screen`, `Route`, `DESTINATIONS`)
   rather than a number a reader has to re-verify.
9. **`api.ts` guards a shape it also mirrors by hand, twice.**
   `web/src/objects.ts:65` and `:69` define private `isStoredObject` and
   `isRefusedObject` that are character-for-character the exported guards at
   `api.ts:966` and `api.ts:998` — and `objects.ts` already imports four other
   combinators from `api.ts` on the line above. Two declarations of one shape is
   exactly what `wire.ts` exists to make impossible.
   *Fix:* import them.
10. **The wire pin's own claim is not quite true.** `wire.ts:31` says "WHAT IS
    PINNED: every payload the app consumes", and pins 45 of the generated
    `wire.ts`'s 51 types. Three of the six omissions are consumed:
    `SpecNode` and `ExplainNode` (rendered generically by `explain.ts` and
    `todoview.ts`) and `ErrorPayload` — the last of which `api.ts:1084`
    re-declares inline (`isObject(payload) && isString(payload["error"])`) as
    the sentence every refused write shows the reader. (`TipPayload`,
    `PostedObjects` and `DevicePayload` are genuinely unconsumed and their
    absence is correct.)
    *Fix:* pin the three, and if `SpecNode`/`ExplainNode` will not pin because
    ts-rs writes an intersection where `api.ts` writes an index signature, say
    so in the file the way the map-carrying block already does.
11. **`Entry.state` is a string, and five files compare it to literals.**
    The generated wire says `state: string` with "`open` | `completed` |
    `cancelled`" in a *doc comment* (`generated/wire.ts:178`), `isEntry` accepts
    any string, and `todos.ts:90`, `todoview.ts:90`, `pages/graph.ts:180,388`,
    `pages/links.ts:267,333` and `card.ts:198` each test it against a literal.
    A state the box renamed would render silently as "open" everywhere. Same
    shape for `Entry.claimed`, `ProposalRow.state`/`outcome` (`proposal.ts:78,83`),
    `TurnRow.who` (`conversation.ts:39`) and `MailRow.disposition`
    (`mail.ts:28` — which at least handles the default arm explicitly and says
    why). CLAUDE.md's rule is sums over records-with-a-bool and parse-don't-
    validate at boundaries; here the boundary parses a string and the union
    lives in prose. This is a wire-level decision (`app/core/src/wire.rs:503`),
    so the honest fix crosses into Rust.
    *Fix (web-side, today):* `todos.ts` gains `isOpen(entry)` beside `isDone`,
    and the five files stop spelling the literal. *Fix (properly):* `wire.rs`
    declares `state` as an enum, ts-rs emits the union, `isEntry` narrows.
    Raise it as a `suzatary`-chain todo rather than doing it in this series.
12. **Four hand-rolled date printers and three private `pad`s.**
    `series.ts:39/79` (`formatInstant`, `formatDate`, with `pad` at :36),
    `stale.ts:38` (`when`, with its own `two`), `mail.ts:60` (`whenOf`, with its
    own `pad`), `todos.ts:294` (`ageLabel`). Beside them `format.ts:31` exports
    `iso(value)` = `value.replace("T", " ")` — and `pages/graph.ts:224,233,303`
    and `pages/history.ts:203` write `.replace("T", " ")` inline anyway, while
    six sites write `.slice(0, 10)` for "the day". Every one of these is a
    presentation decision about the same three shapes (an instant, a day, an
    age), and they are scattered across five modules.
    *Fix:* `format.ts` becomes the one place: keep `iso`, add `day(value)` and
    move `stale.when` and `mail.whenOf` in beside them; `series.ts` keeps only
    the two functions that produce *wire* shapes (`formatInstant`,
    `formatMoment`, `formatDate`), which is a different job and should say so.
13. **The breakpoint is now spelled three times, and `layout.ts` says it is
    spelled twice.** `layout.ts:27` `WIDE_MIN_PX = 992` with a comment stating
    the number is written twice (here and `style.css`) *because there is no
    build step to share it*; `style.css` writes `62rem`; and
    `pages/graph.ts:53` adds a third — `const WIDE = 62 * 16;` — with its own
    comment re-deriving the same arithmetic, while `pages/links.ts:42` imports
    `isWide` correctly.
    *Fix:* `pages/graph.ts` imports `isWide` from `layout.ts`; delete `WIDE`.
14. **`pages/history.ts:44` re-types `DEFAULT_FILTER`.**
    `const OPEN: Filter = { state: "open", category: { tag: "any" }, kind: { tag:
    "any" }, query: "", attention: false }` is field-for-field `todos.ts:75`'s
    `DEFAULT_FILTER`, and it spells the `Choice` constructor inline rather than
    importing `ANY`. A facet added to `Filter` will compile-error here and be
    filled in by whoever is fastest, in two places.
    *Fix:* `import { ANY, DEFAULT_FILTER }` and use it, with the comment about
    why history's filter is fixed rather than remembered kept.
15. **`route.hrefOf` is "one place that knows how a hash is spelt", and two
    pages spell one themselves.** `pages/graph.ts:224` and `pages/chain.ts:94`
    both build `` `#/todo/${encodeURIComponent(id)}` `` by hand.
    *Fix:* `hrefOf({ page: "todo", id })`, two lines.
16. **`web/src/pages/doc.ts:30` fetches outside `api.ts`.** A raw
    `fetch(base + "?page=…", {method:"HEAD"})`, up to 40 times sequentially, is
    the only wire call in the tree that does not go through `getJSON`/`postJSON`.
    It is not a JSON route so it cannot be guarded, but "the wire lives in
    `api.ts`" is the rule and the file is the only exception, unstated.
    *Fix:* move it to `api.ts` as `docPages(base, bust): Promise<number>` beside
    the other route functions, with the ceiling and the 404 contract documented
    there.
17. **`rich.ts`'s hardening pass is the least-tested safety-relevant code in the
    tree.** `harden()` (`rich.ts:65`) sets `rel="noopener noreferrer"` and
    `target="_blank"` on every outbound anchor and rewrites `todo:<id>` to
    `#/todo/<id>` — a rule CLAUDE.md states by name in the Layout paragraph.
    There is no node test (it needs a DOM), and no browser scene mentions
    `todolink` or `noopener`. The other rules of the same weight — `stale.ts`'s
    sentences (`e2e/offline.test.ts:117,164`), `nav.ts`'s five-slot rule
    (`test/nav.test.ts`, "five slots, eleven destinations"), `keys.ts`'s negative
    properties (`test/keys.test.ts`, "typing eats everything but Escape") — are
    all pinned, so this one gap stands out.
    *Fix:* one browser scene over the fixture chain's linked todo: the rendered
    anchor's `href` is `#/todo/<id>`, it carries no `target`, and an external
    anchor carries `rel="noopener noreferrer"`.
18. **`chain.ts:61`'s slug guard has no test.** `isChainName` is the parse that
    stops a hand-edited `localStorage` value from becoming `/api/../fold` — its
    own comment says exactly that — and it is one of the few pure functions in
    `web/src` with no node test. `theme.ts`'s equivalent three-line guard has
    one (`test/theme.test.ts`).
    *Fix:* a `chain.test.ts` beside `theme.test.ts`: the slug accepts, `..` and
    `A` and `""` and a 40-character name reject, and an unreadable store opens
    on `life`.
19. **Seven unchecked casts in `reconcile.ts`, two in `focus.ts`.**
    `reconcile.ts:39,44,47,51,54,80,84` write `as number` / `as string` to
    silence `noUncheckedIndexedAccess` inside the longest-increasing-subsequence
    — the algorithm that decides which DOM node moves. `focus.ts:53–54` casts
    `list[0]`/`list[list.length-1]` two lines after an early return that already
    proves the array is non-empty. CLAUDE.md forbids unchecked casts; these are
    locally sound but they are assertions, and `tsconfig`'s
    `noUncheckedIndexedAccess` was turned on to stop exactly this.
    *Fix:* `focus.ts` — destructure with `?? undefined` and a `=== undefined`
    guard (three lines). `reconcile.ts` — the LIS reads a `readonly number[]`;
    hoist `const value = values[index]; if (value === undefined) continue;` and
    let the rest follow, or carry the array as a `Int32Array`, which is not
    optional-indexed.
20. **`draft.ts:64`'s `priceOf` returns `Drafted | Priority` and the caller
    discriminates with `"ok" in price`.** The two arms of the union are only
    distinguishable by a key one of them happens not to have; `Priority` gaining
    an `ok` field would be a silent mis-parse. The file's own header says errors
    are values and the neighbouring `Drafted` is a proper tagged union.
    *Fix:* `priceOf` returns
    `{ok: true, price: Priority} | {ok: false, problem: string}`.
21. **A ternary with two identical branches, in a sentence a person reads.**
    `pending.ts:102`: `${reasons.length === 1 ? "objects" : "objects"}` — so a
    single refusal reads "The box refused 1 of this browser's objects — it cannot
    be sent." The neighbouring branch pluralises correctly, and the string is
    the app's report about lost work.
    *Fix:* `"object" : "objects"`.
22. **Two colours are still decided in TypeScript.** `series.ts:217`
    `colourFor(todo)` returns `hsl(<hash> 62% 46%)` — a fixed lightness that does
    not move with the theme — and `pages/graph.ts:207,308` inline it as
    `style: \`background:${colourFor(...)}\``. `card.ts:73` had this exact
    argument settled in this pass ("The bar used to carry an inline `width`,
    which was one length TypeScript had an opinion about"); the identity colour
    genuinely cannot be a CSS token, but its *lightness* can be.
    *Fix:* hand the hue across as `--hue` and let `style.css` write
    `hsl(var(--hue) 62% var(--track-l))`, with `--track-l` in the two palette
    blocks.
23. **Four small CSS restatements.** `style.css:357` `font-size: 15px` (the one
    raw px font size, against a stylesheet whose whole opening comment is "one
    type scale"); `.tab` at `:301` uses `min-height: 3.25rem` where `--tap`
    exists and its comment says the 44 px claim is "checkable by reading rather
    than by measuring"; five raw `rgba(0,0,0,…)` scrims and shadows at
    `:1766,1786,2653,2663,2714` where `--shadow`/`--shadow-deep` are tokens; four
    raw hexes (`#fff`) past line 200. Everything else in 3,491 lines goes
    through tokens, both palette blocks are complete and equal, and
    `prefers-reduced-motion` is honoured at `:424` — this is drift at the edges
    of a stylesheet that is otherwise the best-disciplined file in the tree.
    *Fix:* `--t-body` for the 15px, `var(--tap)` for `.tab`, a `--scrim` token
    for the five rgba, `var(--on-accent)` for the hexes.
24. **`nodejs` is an unversioned attribute under three "node 24" claims.**
    `flake.nix:507` takes `esbuild typescript nodejs` from a locked nixpkgs, so
    the build is reproducible — but `scripts/web-test.sh:11`,
    `scripts/build-web.sh` and `flake.nix:513` all assert *node 24* by name
    (global `WebSocket`, `crypto.subtle`, `--test` semantics), and a nixpkgs
    bump moves the alias with only a test failure to say so. `uplot` next door
    is pinned as `uplot-1.6.31` by hash, and the Rust toolchain is explicit.
    Nothing is fetched at build time except uPlot's two files, which are
    content-addressed.
    *Fix:* `nodejs_24`.

## Not findings

Stated so they are not re-raised.

- **`api.ts` at 1,215 lines.** It is one concern — the wire — with real internal
  seams (`// --- json_entry ---`), and splitting types from guards would be
  splitting a declaration from its parse. The mixed pure/effectful shape
  (guards beside `fetch`, `chainMemo`, `ourTip`) is the file being the boundary,
  which is where a boundary belongs.
- **`chain.ts` and `theme.ts` having the same shape** (a `KEY`, a parse, a
  module `let`, a listener `Set`, `watchX`/`setX`). Two ~100-line modules that
  rhyme is not a duplication worth a generic; the values they hold have
  different lifetimes and different consequences, and a shared `remembered<T>()`
  would obscure that `setChain` returns whether it moved and `setTheme` does not.
- **`core.ts` at 658 lines and `todoview.ts` at 631.** One concern each — the
  Wasm boundary, and a todo — and both have a clear shell/pure split inside.
- **The N+1 in `pages/inbox.ts:51`.** It is called out in the file's own header
  with the reason (there is no route that returns every standing proposal, and
  composing one on the client would be the page answering a question the box
  should answer) and the place to fix it named. That is a decision, not drift.
- **`replica.ts::parentsOf` and `waitingTodos` scanning the literal with a
  regex.** Both headers state the rule they are not breaking, the box
  re-derives and refuses, and the tests pin the negative case ("a hex-looking
  string inside the event is not a parent").
- **`localStorage` used by four modules.** All four go through `local.ts`'s
  try/catch and all four parse on the way back; the header's *count* is stale
  (finding 8), the design is not.
- **The two dark-palette blocks in `style.css`.** The duplication is deliberate,
  stated, and unavoidable without a build step; the two blocks are equal today.
- **The route/screen split (`route.ts` + `layout.ts`) and `nav.ts`'s
  `TABS`/`OVERFLOW`.** Exhaustive, pure, node-tested, and the 2026-09-10 change
  to which four get a slot is argued in the file rather than asserted. This is
  the part of the pass that landed cleanest.
- **`sync.ts`'s dynamic `import("./toast")`.** One lazy import to keep a
  DOM-free module DOM-free reads as clever, but it is one line with its reason
  beside it and it is what lets `sync.ts` be reachable from a node test.
